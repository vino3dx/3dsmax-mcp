## 2. 新增工具清单（命名遵循现有 `mod_*` / `poly_*` 规范）

| 工具 | 桥接命令 | 说明 |
|---|---|---|
| `mod_toggle` | `mod_toggle` | 翻转修改器启用状态，回读验证（enabledBefore/After/verified） |
| `mod_collapse` | `mod_collapse` | 整栈塌陷；**必须 `confirm=true`**；`modifier` 参数作批量安全过滤；报告 before/after 堆栈数 |
| `mod_chamfer` | `mod_add`（预设 Chamfer） | Chamfer 修改器：amount/segments/openEdges/smoothOnIntersections；类不存在时 `mcpEnsureClass` 返回明确错误 |
| `poly_get_selection` | `poly_get_selection` | 只读：子对象层级 + 点/边/面/边界各级的数量与索引（分页、截断标记） |
| `poly_select` | `poly_select` | 设置子对象层级（0-5 或名称，可自动推断）+ 点/边/面/边界/元素选择；元素索引自动展开为面 |
| `poly_get_elements` | `poly_get_elements` | 元素（连通面分组）数量与各元素面数 |

**未重复实现的既有能力**（盘点后确认已存在，直接复用）：`mod_list`、`mod_add`、`mod_get_params`、
`mod_set_param(s)`、`mod_remove`、`mod_enable/disable`、`mod_reorder`、`convert_to_editable_poly`、
`poly_extrude/inset/bevel/chamfer/connect/weld/cap`、`poly_loop_select`、`poly_ring_select` 等 60 余个工具。

### 兼容性与防护设计

- 元素查询双策略：优先 `polyop.getElementsUsingFace`（已验证存在于 2020），失败时退回到仅用
  `getFaceVerts`/`getEdgeVerts` 的边邻接泛洪（每个面必须被覆盖一次的校验）。
- 边界选择：`polyop.getBorderSelection/setBorderSelection` 经文档确认不存在——查询返回
  `supported:false`，设置返回 `bordersApplied:false`，**不假装成功**。
- 所有写操作包在 `theHold`（undoable 注册）、逐对象 try/catch、`applied/failures` 汇总；
  选择类工具刻意保留选择；操作后重置 `subobjectLevel`。
- 消息走中央双语表（`mcp_core.ms`），语言切换全局生效。

## 4. 未解决问题

1. **3ds Max 启动崩溃**（见 §3.2）——阻塞所有真实实例测试，需用户在本机处理。
2. `polyop.getBorderSelection/setBorderSelection` 不存在（文档确认），边界选择只能查询
   `supported:false` / 设置 `bordersApplied:false`；后续可用 `getOpenEdges`/`getBorderFromEdge` 或
   `Editable_Poly.ConvertSelection #Edge #Border` 做等价实现。
3. `mod_collapse` 只支持整栈塌陷：MAXScript 无单修改器塌陷接口（"Collapse To" 只能快照-删除-重建，
   会丢失子对象编辑数据），已在工具描述中明确说明，未做危险的部分塌陷仿真。
4. Swift Loop 无脚本 API（`macros.run "PolyTools" "SwiftLoop"` 为交互式，会中断脚本）——
   capability matrix 给出 divideEdge+createEdge 的脚本化等价方案，尚未实现与实测。
